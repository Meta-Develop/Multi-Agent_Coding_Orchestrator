# Gemini managed bootstrap, phase J

This is an offline, version-bound installed-module test unit, not a Gemini launch
capability. `loadOfflineCodeAssist` requires a private Linux profile and denied
network, and exposes an explicitly synthetic physical sink. It cannot authorize
credentials, CLI main, provider generation, Rust custody, model/effort identity,
whole-invocation usage, USD eligibility, publication or writable execution.
The static Gemini Rust capabilities and terminal JSON observer are unchanged.

## Pinned loading and guards

Node 22.22.2 installs synchronous `registerHooks` before importing the canonical
Gemini 0.41.2 core and extension chunks. The allowlist contains the twelve actual
imported JavaScript files. Every load hashes the bytes returned by Node's load
hook and executes the resulting instrumented source. Alternate paths, query or
fragment aliases, unknown dependencies, changed bytes and missing load receipts
(including prior cached evaluation) refuse. The trusted Node executable is a
separate verification-receipt binding; builtins are not third-party closure files.
Pinned optional lookups (`encoding` at Z:6816, `bufferutil`/`utf-8-validate` at
664:88/727, and `long` through Z:24203/24485) are explicitly denied with
MODULE_NOT_FOUND before resolution, including if a package exists. Their
observed absence is recorded and no optional bytes execute. A uses its own
strict UTF-8/JSON decoder. Other unresolved imports latch refusal.

Four source insertion categories are guarded by original whole-file SHA256 and
single-match literal anchors: Config entry, OAuth factory credential/client
boundaries, CodeAssist constructor exit, and GoogleGenAI constructor entry.
Only Z and X change in memory. The appended OAuth2Client export is an owned
TEST_ONLY seam exposing the actual bundled class, not an original vendor API.
No vendor source is copied, forked or written in the Nix store.

The actual extension chunk initializes embedded Yoga WASM with a `data:` fetch.
The bootstrap permits only that exact data value extracted from the SHA-bound
chunk, decoding it locally. It grants no network authority. All other global
fetches, including user-info, refuse and latch cancellation. HTTP/TLS/socket and
subprocess entry points are denied before vendor imports, backed by the test's
network and mount namespaces.

Config admits only the five owned data parameters (sessionId/model/cwd/targetDir/
debugMode), with exact `/candidate` paths. Unknown fields and accessors refuse;
required MCP/admin/config inputs cannot be silently erased into permission.
Actual constructor parameters disable MCP, extensions, agents, hooks, skills,
plan/tracker, ADK sessions, Gemma/autostart, JIT/automatic memory, Conseca,
telemetry/statistics, automatic repair and interactive/browser entry. Extension
loading returns an owned empty set; startup/install/reload and MCP/LiteRT routes
refuse. SDK construction refuses before reading its supplied options.

Only the actual ReadFileTool class/name pair is admitted by ToolRegistry.
Its real build and invocation execute boundaries revalidate relative regular-file
paths, canonical resolution and hidden-root exclusion. The candidate is mounted
read-only, so path validation is not relied on to secure a writable snapshot.
Other classes, same-name fakes, shell, web, MCP and native delegation are refused.
Caught refusals latch the bridge. Actual Logging generation methods verify their
registered CodeAssist backend on every call. Direct server generation is also
serialized; a still-active stream blocks another generation.

## Physical send ownership

A WeakMap binds each actual OAuth client to its exact original transporter,
Gaxios shape and one wire unit. Two actual CodeAssist instances sharing that
client reuse its binding; a fresh client gets a fresh binding. Cross-unit reuse,
changed method/default/interceptor shapes, custom refresh handlers and borrowed
transport receivers refuse. Optional telemetry methods are disabled locally.

Generation still uses A's request adapters and raw before-translation decoder;
actual CodeAssist generation, Logging, OAuth request/requestAsync, and Gaxios
preparation/response methods execute. Only the final Gaxios `fetchImplementation`
option is replaced by the named offline sink. This replacement is not available
through arbitrary native request options: adapter/fetch overrides are cleared.
The sink does not confer production authority.

The only newly admitted non-generation class is exact OAuth refresh **inside an
already owned request context**: POST to the pinned token URL, unique bounded
refresh-token/client fields, no redirect or hidden retries. It requires its own
admission/release/terminal ACK and bounded strict response decoding. A 401/403
replay then requires another generation admission. Token refresh response bodies
are never exported as usage or evidence. All unscoped startup token-info,
setup/onboarding/quota/admin/experiments requests and unclassified endpoints
refuse; the offline credential factory always refuses. Implementing a real auth
and startup admission channel belongs to the later authorized Rust/bootstrap
integration, not to this synthetic proof. No broad non-generation passthrough
exists. Unknown usage, cost and quiescence remain unknown.

## Offline verification

Run both `.test.mjs` files with pinned Node in the retained official delegated
user-systemd wrapper. Set `MACO_CODE_ASSIST_PUBLIC_SOURCE` to the pinned Z source
for A's binding test. Each installed-module scenario creates a transient owned
user/mount/network/PID namespace, tmpfs root, empty private profile and substantive
read-only candidate text. Only the pinned store and owned modules are mounted
read-only; owner homes, mounted drives, ancestor profiles and credentials are not
visible. The bootstrap verifies the profile/environment, read-only mounts,
loopback-only/down network and delegated cgroup before any vendor import.
Cleanup removes only the empty namespace-root directory, never recursively.

Tests exercise real installed unary/stream and 401-refresh-replay control flow,
shared/fresh clients, guard-before-effect refusals, actual substantive file
reading, source/cache/profile guards and ownership drift. A's existing 24 tests
remain intact; added refresh tests retain unknown usage and conservative abort
semantics. Tests never call main/getOauthClient/refreshAuth, real credentials or
providers. Synthetic success is not actual authentication or managed execution.

Phase J deliberately has no private peer protocol, provider-release authority,
NotStarted refund witness or ledger integration. Root must separately assign and
review those coupled Rust/launcher pieces before any real route qualification.
